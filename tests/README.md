# minimap2 Unit Tests

Unit tests for minimap2 using Google Test (gtest). Covers the CPU mapping pipeline (seed, chain, align) and GPU chaining/alignment.

## Directory Structure

```
tests/
├── README.md                        # This file
├── CMakeLists.txt                   # Top-level test config (includes core/ and gpu/)
├── core/                            # CPU tests (test_core binary)

│   ├── test_kalloc.cpp              # Memory pool allocator tests
│   ├── test_map.cpp                 # Full pipeline (mm_map) tests
│   ├── test_map_seed.cpp            # Seeding (mm_map_seed) tests
│   ├── test_map_chain.cpp           # Chaining (mm_map_chain) tests
```

## Test Architecture

Tests follow a dual-pattern architecture:

| Pattern | Style | Scope | Purpose |
|---------|-------|-------|---------|
| **Parameterized** | `TEST_P` | All datasets | Exact-match verification against CPU baselines |
| **Behavioral** | `TEST_F` | Single representative dataset | Structure, determinism, and invariant checks |

### Core Tests (test_core)

| Test File | Parameterized Tests | Behavioral Tests |
|-----------|-------------------|------------------|
| `test_kalloc.cpp` | — | Memory pool init, alloc, realloc, calloc |
| `test_map_seed.cpp` | `LoadTestData`, `MapRealSequence` | Determinism, edge cases, flag effects, occupancy |
| `test_map_chain.cpp` | `ChainPropertiesAndValidation` | Determinism, mode variants, constraints |
| `test_map_align.cpp` | `VerifyCpuOutput` | Determinism, quality metrics, flag variants |
| `test_map.cpp` | `VerifyCpuOutput` | Mode tests, secondary alignments, MAPQ |

### GPU Tests (test_gpu)

| Test File | Parameterized Tests | Behavioral Tests |
|-----------|-------------------|------------------|
| `test_gpu_chain.cpp` | `GpuChainFromConstantAnchors`, `VerifyAllChainsVsCpuBaseline` | Determinism, structure/ordering |
| `test_gpu_align.cpp` | `VerifyAllAlignmentsVsCpuBaseline`, `VerifyGpuChainCpuAlignVsBaseline`, `VerifyFullGpuPipelineVsCpuBaseline` | Determinism, quality metrics, flag variants |

### Pipeline Combinations Tested

| Test | Seed | Chain | Align |
|------|------|-------|-------|
| Core `VerifyCpuOutput` | CPU | CPU | CPU |
| `VerifyAllChainsVsCpuBaseline` | CPU | **GPU** | — |
| `VerifyAllAlignmentsVsCpuBaseline` | CPU | CPU | **GPU** |
| `VerifyGpuChainCpuAlignVsBaseline` | CPU | **GPU** | CPU |
| `VerifyFullGpuPipelineVsCpuBaseline` | CPU | **GPU** | **GPU** |

## Test Data

All test data is defined in JSON files under `test_suite/*/expected/`. Each JSON file references FASTA files and contains expected seeds, chains, and alignments generated by the CPU pipeline.

### Adding New Test Data

1. Place reference/query FASTA files in the appropriate `test_suite/` subdirectory.
2. Run `scripts/generate_test_data.py` to produce a JSON file with expected outputs.
3. No C++ changes needed — parameterized tests auto-discover all JSON files.

### Generating Test Data

```bash
# Generate test data for a single pair
python3 scripts/generate_test_data.py \
    --ref test_suite/original/MT-human.fa \
    --query test_suite/original/MT-orang.fa \
    --output test_suite/original/expected/MT_human_vs_orang.json

# Generate all test data using presets
./scripts/generate_all_test_data.sh
```

## Building and Running Tests

### Prerequisites

- CMake 3.18+
- C++11 compatible compiler
- Google Test (automatically fetched by CMake)
- GPU tests additionally require: AMD GPU with ROCm/HIP

### Quick Start

```bash
# CPU-only build
cmake --preset test-cpu
cmake --build --preset test-cpu -j$(nproc)
ctest --test-dir out/test-cpu/build --output-on-failure

# GPU build (AMD)
cmake --preset amd-default
cmake --build --preset amd-default -j$(nproc)
ctest --test-dir out/amd-default/build -j$(nproc) --output-on-failure
```

### Running Tests in Parallel

Core tests run in parallel via `ctest -j`. GPU tests are registered as a single CTest entry (to avoid repeating the expensive ~9.5s GPU initialization per test) with a `RESOURCE_LOCK` to prevent concurrent GPU access.

```bash
# Run all tests: core in parallel, GPU serialized automatically
ctest --test-dir out/amd-default/build -j$(nproc) --output-on-failure

# Output results to a log file
ctest --test-dir out/amd-default/build -j$(nproc) --output-on-failure \
    --output-log ctest_output.txt
```

### Running Specific Tests

```bash
# Run tests matching a pattern (ctest)
ctest --test-dir out/amd-default/build -R "Kalloc" --output-on-failure

# Run specific test directly with gtest filter
./out/amd-default/build/tests/core/test_core --gtest_filter="KallocTest.*"

# Run parameterized tests for a specific dataset
./out/amd-default/build/tests/core/test_core --gtest_filter="*MT_human_vs_orang*"

# Run GPU tests directly
./out/amd-default/build/tests/gpu/test_gpu --gtest_filter="*GpuChain*"

# List all available tests
./out/amd-default/build/tests/core/test_core --gtest_list_tests
./out/amd-default/build/tests/gpu/test_gpu --gtest_list_tests
```

### Available Test Presets

| Preset           | Description                        | GPU Support |
|------------------|------------------------------------|-------------|
| `test-cpu`       | CPU build with tests               | No          |
| `amd-default`    | AMD GPU build with tests           | Yes         |
| `coverage`       | GCC/gcov coverage with tests       | Yes         |
| `coverage-clang` | Clang/llvm-cov coverage with tests | Yes         |

## Code Coverage

### Generating Coverage Reports

Use the automated coverage script:

```bash
# Clang/llvm-cov coverage (default, includes host-side GPU code)
./scripts/coverage.sh
./scripts/coverage.sh --clean              # Clean rebuild

# GCC/gcov coverage (CPU-only)
./scripts/coverage.sh --compiler gcc
./scripts/coverage.sh --compiler gcc --clean

# Generate specific format only
./scripts/coverage.sh --format html
./scripts/coverage.sh --format xml --compiler clang

# View help
./scripts/coverage.sh --help
```

The script will:
1. Build minimap2 with coverage instrumentation (GCC or Clang)
2. Run all unit tests
3. Capture coverage data
4. Generate reports: HTML, XML (Cobertura), JSON, Markdown

### Coverage Output

**GCC/gcov** (in `out/coverage/build/coverage/`):
- `html/index.html` - Interactive HTML report
- `coverage.xml` - Cobertura XML for CI/CD
- `coverage.json` - gcovr JSON format
- `coverage.md` - Markdown summary

**Clang/llvm-cov** (in `out/coverage-clang/build/coverage/`):
- `html/index.html` - Interactive HTML report
- `coverage.xml` - Cobertura XML for CI/CD
- `coverage.json` - Native llvm-cov JSON format
- `coverage.md` - Markdown summary
- `coverage.lcov` - LCOV tracefile (intermediate)

### Manual Coverage Generation (GCC)

If you prefer manual steps with GCC/gcov:

```bash
# 1. Configure with coverage
cmake --preset coverage

# 2. Build with coverage flags
cmake --build --preset coverage -j$(nproc)

# 3. Run tests to generate .gcda files
ctest --test-dir out/coverage/build --output-on-failure

# 4. Capture baseline coverage (all instrumented files)
cd out/coverage/build
lcov --capture --initial --directory . --output-file coverage_base.info \
     --rc branch_coverage=1 --ignore-errors mismatch,source

# 5. Capture test execution coverage
lcov --capture --directory . --output-file coverage_test.info \
     --rc branch_coverage=1 --ignore-errors mismatch,source

# 6. Combine baseline and test coverage
lcov -a coverage_base.info -a coverage_test.info -o coverage.info \
     --rc branch_coverage=1 --ignore-errors mismatch

# 7. Filter out external dependencies
lcov --remove coverage.info '/usr/*' '*/tests/*' '*/cJSON/*' \
     '*/_deps/*' '*/googletest/*' \
     --output-file coverage_filtered.info --rc branch_coverage=1

# 8. Generate HTML report
genhtml coverage_filtered.info --output-directory coverage_html \
        --rc branch_coverage=1 --title "minimap2 Code Coverage" --legend
```

### Understanding Coverage Metrics

The coverage report provides three metrics:

- **Line Coverage**: Percentage of executable lines that were executed
- **Function Coverage**: Percentage of functions that were called
- **Branch Coverage**: Percentage of conditional branches that were taken

**Example Output:**
```
Summary:
  lines......: 1.3% (65 of 4932 lines)
  functions..: 2.6% (7 of 271 functions)
  branches...: 0.7% (32 of 4830 branches)
```

### Coverage Best Practices

1. **Filtered Results**: External dependencies (googletest, system headers, cJSON) are excluded
2. **Branch Coverage**: Enabled for both GCC and Clang to test conditional logic
3. **Incremental Builds**: Regenerate reports quickly with `--skip-build` flag
4. **CI Integration**: Use `--format xml` for Cobertura XML compatible with most CI systems
5. **Compiler Choice**: Clang/llvm-cov provides more detailed region coverage metrics

## Writing New Tests

### Test File Template

Create a new test file in `tests/core/`:

```cpp
#include <gtest/gtest.h>

extern "C" {
#include "minimap.h"
#include "your_module.h"
}

// Test fixture for your module
class YourModuleTest : public ::testing::Test {
protected:
    void SetUp() override {
        // Setup code here
    }
    
    void TearDown() override {
        // Cleanup code here
    }
};

TEST_F(YourModuleTest, TestName) {
    // Your test code here
    EXPECT_EQ(expected, actual);
}
```

### Adding Tests to Build

1. Create your test file: `tests/core/test_yourmodule.cpp`
2. Add it to `tests/core/CMakeLists.txt`:

```cmake
add_executable(test_core
    test_kalloc.cpp
    test_map_seed.cpp
    test_map_chain.cpp
    test_map_align.cpp
    test_yourmodule.cpp  # Add your test here
)
```

3. Rebuild and run tests

### Test Naming Conventions

- **Test Files**: `test_<module>.cpp`
- **Test Fixtures**: `<Module>Test`
- **Test Cases**: Descriptive names using PascalCase (e.g., `SimpleAllocation`, `EdgeCaseHandling`)

### Common Test Assertions

```cpp
// Equality
EXPECT_EQ(expected, actual);    // Non-fatal
ASSERT_EQ(expected, actual);    // Fatal

// Boolean
EXPECT_TRUE(condition);
EXPECT_FALSE(condition);

// Null checks
EXPECT_NE(ptr, nullptr);
EXPECT_EQ(ptr, nullptr);

// Floating point comparison
EXPECT_DOUBLE_EQ(expected, actual);
EXPECT_NEAR(expected, actual, tolerance);

// String comparison
EXPECT_STREQ("expected", actual);
```

### Validation Constraints

| Stage | Validation | Description |
|-------|------------|-------------|
| Seed | Anchor bounds | q_pos < query_len, q_span > 0 |
| Seed | Value matching | x, y values match expected |
| Chain | Colinearity | Anchors sorted by query position within chains |
| Chain | Structure | Chain score and length extraction |
| Align | Coordinates | qs, qe, rs, re within valid bounds |
| Align | Reference bounds | rid < n_seq, re <= ref_len |
| Align | CIGAR validity | All operations valid, lengths > 0 |
| Align | Span ratio | Query/ref span within 10x |
| Map | Secondary alignments | Valid coordinates, scores, reference IDs |
| Map | MAPQ range | 0 <= mapq <= 60 |
| GPU Chain | Baseline match | GPU chain output matches CPU chain output |
| GPU Chain | Determinism | Repeated runs produce identical results |
| GPU Align | Baseline match | GPU align output matches CPU align output |
| GPU Align | Determinism | Repeated runs produce identical results |
| GPU Pipeline | Isolation | GPU chain + CPU align vs full GPU pipeline |

### Known Issues

- **hg00438 dataset**: GPU chaining produces non-deterministic chain counts (7731/7733/7861 across runs) that diverge from the CPU baseline. All 3 GPU test failures are on this dataset. The `VerifyGpuChainCpuAlignVsBaseline` test confirmed the divergence originates in GPU chaining, not alignment.

## Continuous Integration

Tests can be integrated into CI pipelines:

```bash
# Run tests and fail on any error
cmake --preset coverage
cmake --build --preset coverage -j$(nproc)
ctest --test-dir out/coverage/build --output-on-failure
if [ $? -ne 0 ]; then
    echo "Tests failed!"
    exit 1
fi
```

## Debugging Tests

### Run Specific Tests

```bash
# Run a specific test by name
ctest --test-dir out/coverage/build -R KallocTest.SimpleAllocation -V
```


